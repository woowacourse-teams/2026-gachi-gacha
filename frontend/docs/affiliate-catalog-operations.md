# 쇼핑 커넥트 카탈로그 운영 가이드

## 목적

운영자는 네이버 쇼핑 커넥트에서 제휴 링크를 발급하고 Google Sheet에 공개 상품 정보만 입력한다. GitHub Actions는 입력을 검증하고 기존 가치가챠 카테고리 ID를 찾아 정적 프론트 카탈로그 PR을 만든다. 백엔드와 별도 DB는 사용하지 않는다.

시트는 자동 실행 트리거가 아니다. 여러 상품을 천천히 입력한 뒤 운영자가 Actions에서 한 번 실행해야만 동기화된다.

## Google Sheet 준비

개인정보나 내부 정보가 없는 별도 스프레드시트를 만들고 탭 이름을 `products`로 정한다. 첫 행에는 아래 헤더를 정확히 입력한다.

| 상품제목 | 썸네일URL | 네이버링크 | 카테고리 | 노출페이지 | 노출시작일 | 노출종료일 | 노출여부 |
| -------- | --------- | ---------- | -------- | ---------- | ---------- | ---------- | -------- |

- `상품제목`: 사용자에게 보여줄 제목
- `썸네일URL`: 로그인·쿠키 없이 열리는 HTTPS 이미지 URL
- `네이버링크`: 쇼핑 커넥트에서 발급한 `https://naver.me/...` 링크
- `카테고리`: 가치가챠에 등록된 정확한 한글명. 여러 개면 `산리오|피규어`처럼 `|`로 구분
- `노출페이지`: `/search` 또는 `https://gachigacha.kro.kr/search`. 여러 개면 `/search|/trade/123`처럼 구분
- `노출시작일`, `노출종료일`: `YYYY-MM-DD`. 비워 두면 시작·종료 제한 없음
- `노출여부`: `TRUE` 또는 `FALSE`. 비워 두면 `TRUE`

표시 순서는 활성 행의 위에서 아래 순서로 자동 결정된다. 상품 ID는 첫 카테고리 ID와 제휴 링크의 해시로 생성되므로 행을 옮겨도 유지된다. 같은 제휴 링크를 여러 행에 복제하지 말고 한 행의 카테고리·페이지 셀에 여러 값을 적는다.

## CSV 게시

Apps Script는 필요하지 않다. Google Sheet의 **파일 → 공유 → 웹에 게시**에서 `products` 탭과 CSV 형식을 선택해 게시 URL을 복사한다.

시트를 링크로 공개한 경우 다음 형식도 사용할 수 있다.

```text
https://docs.google.com/spreadsheets/d/{SHEET_ID}/gviz/tq?tqx=out:csv&sheet=products
```

이 URL을 GitHub 저장소의 **Settings → Secrets and variables → Actions → Variables**에 아래 이름으로 등록한다.

```text
AFFILIATE_CATALOG_SHEET_CSV_URL
```

카탈로그 정보와 제휴 링크는 실제 웹 화면에도 공개되므로 repository secret 대신 variable을 사용한다. 스프레드시트에는 공개해도 되는 상품 정보만 둔다.

## 동기화

1. 상품 행을 모두 입력하고 `FALSE` 행과 날짜를 확인한다.
2. GitHub **Actions → Affiliate Catalog Sync → Run workflow**를 연다.
3. 기본 카테고리 API 주소를 유지하고 실행한다.
4. 검증이 성공하면 `frontend-dev` 대상 자동 PR이 생성된다.
5. 변경된 상품·기간·카테고리를 확인하고 PR을 병합한다.

시트 저장 자체로는 Actions가 실행되지 않는다. 수십 개 행을 입력하는 동안 실행 로그나 PR이 생성되지 않으며, 입력을 끝낸 뒤 한 번만 실행하면 된다. 생성 결과가 기존 카탈로그와 같으면 PR도 만들지 않는다.

GitHub의 조직 정책에 따라 자동 PR이 차단되면 저장소의 Actions 설정에서 **Allow GitHub Actions to create and approve pull requests**를 활성화해야 한다. 승인 기능은 사용하지 않고 PR 생성 권한만 사용한다.

## 검증 규칙

- 카테고리는 기존 `/api/v1/categories?keyword=...` 결과 중 한글명이 정확히 같은 항목 한 개만 허용한다.
- 오타 또는 여러 후보가 있으면 임의로 선택하지 않고 행 번호와 후보를 출력하며 중단한다.
- 제휴 링크는 HTTPS `naver.me` 링크만 허용한다.
- 썸네일과 노출 페이지도 HTTPS·가치가챠 경로 규칙을 검사한다.
- 중복 제휴 링크, 잘못된 날짜 범위, 필수 셀 누락이 있으면 PR을 만들지 않는다.

## 이미지와 노출 페이지

개발자 도구에서 복사한 이미지 URL도 공개 URL이면 `<img>`로 표시된다. 다만 토큰·만료 시간이 포함된 URL, 로그인 쿠키가 필요한 URL, 외부 핫링크를 막는 URL은 나중에 사라질 수 있다. 프론트는 8초 안에 이미지를 불러오지 못하거나 로드 오류가 발생한 상품을 제목과 함께 전부 숨긴다.

현재 실제 카탈로그 슬롯은 `/search` 카테고리 화면에 연결되어 있다. 데이터 계약은 여러 페이지를 지원하지만, 임의 URL의 원하는 위치에 컴포넌트를 자동 삽입하지는 않는다. 다른 화면에 노출하려면 해당 화면의 적절한 위치에 `AffiliateCatalogSection` 슬롯을 한 번 연결해야 한다. 이후에는 시트의 `노출페이지`만으로 해당 슬롯의 상품을 바꿀 수 있다.
