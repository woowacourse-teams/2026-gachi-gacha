# 인증 및 사용자 기능 로드맵

이 문서는 이슈 #132부터 이어질 인증·중고거래·채팅·관심·마이페이지 작업의 공통 기준이다. 화면을 구현할 때는 `ui-guidelines.md`와 함께 적용한다.

## 제품 원칙

- 검색, 지도, 매장 상세는 로그인 없이 계속 사용할 수 있다.
- 교환 글 작성, 채팅, 관심 등록, 알림, 마이페이지처럼 사용자를 식별해야 하는 기능만 로그인을 요구한다.
- 보호 기능에 비로그인 사용자가 접근하면 `/login?returnTo=...`으로 이동하고, 로그인 성공 후 원래 경로로 돌아온다.
- 헤더에서는 채팅, 알림, 계정 진입점을 항상 찾을 수 있게 한다.
  - 비로그인 계정 액션은 사람 아이콘만 두지 않고 `로그인`을 명시한다.
  - 로그인 계정 액션은 프로필 이미지 또는 계정 아이콘으로 마이페이지에 연결한다.
  - 비로그인 상태에서 채팅·알림을 누르면 로그인 화면으로 안내한다.
- 빈 페이지를 노출하지 않는다. 아직 구현되지 않은 목적지는 해당 기능 이름과 준비 중 안내를 보여준다.
- 카카오와 네이버 로그인 버튼은 각 제공자의 공식 디자인 가이드와 자산을 사용하고 임의로 브랜드를 변형하지 않는다.

## 확인된 백엔드 계약

`backend-dev` 기준으로 카카오와 네이버 OIDC 로그인이 모두 구현되어 있다.

| 목적         | 계약                                                 |
| ------------ | ---------------------------------------------------- |
| 로그인 시작  | `GET /api/v1/oauth/{provider}` (`kakao`, `naver`)    |
| 로그인 완료  | `GET /api/v1/oauth/login/{provider}`                 |
| 로그인 응답  | `data.token`에 GachiGacha JWT 반환                   |
| 내 정보      | `GET /api/v1/members/me`                             |
| 내 정보 필드 | `nickname`, `profileImageUrl`, `desireTradeLocation` |
| 인증 전달    | `Authorization: Bearer {token}`                      |

현재 refresh token 발급·갱신, 서버 로그아웃, 토큰 폐기 API는 없다. 따라서 프런트 MVP는 access token을 탭 단위 `sessionStorage`에 보관하고 만료와 `401`을 일관되게 처리한다. 공개 운영 전에는 HttpOnly 쿠키 기반 refresh token 회전과 로그아웃 계약을 백엔드와 별도로 확정한다.

현재 OAuth 완료 엔드포인트는 JSON을 반환한다. 브라우저가 JSON 화면에 머물지 않도록 제공자 콘솔과 서버 환경 변수의 redirect URI를 프런트 콜백(`/auth/callback/{provider}`)으로 맞추고, 콜백 화면이 기존 로그인 완료 API를 호출하는 흐름을 우선 검증한다. 이때 OAuth 시작 과정에서 발급된 서버 세션을 전달하기 위해 콜백 요청에는 credentials 설정이 필요하다.

## 이슈 #132 구현 순서와 커밋 단위

1. `docs: 인증 계약과 사용자 기능 로드맵 기록`
   - 이 문서와 dev/prod 콜백 확인 항목을 기준으로 남긴다.
2. `feat: 인증 API와 세션 상태 기반 추가`
   - 로그인 응답·회원 응답 파서, 토큰 저장소, 인증 요청, 복원·만료·`401` 처리를 구현한다.
3. `feat: 소셜 로그인과 콜백 흐름 추가`
   - `/login`, `/auth/callback/kakao`, `/auth/callback/naver`, 안전한 `returnTo` 복귀를 구현한다.
4. `feat: 로그인 상태별 헤더 액션 추가`
   - 데스크톱과 모바일에서 채팅·알림·로그인/마이페이지 상태를 구현한다.
5. `feat: 사용자 기능 보호 라우팅 추가`
   - 채팅, 알림, 마이페이지 경로에 인증 가드와 준비 중 화면을 연결한다.
6. `test: 인증과 헤더 상태 시나리오 검증`
   - MSW·Storybook으로 게스트, 로그인, 로딩, 실패, 만료 상태를 검증한다.
   - 360px, 767px, 768px, 데스크톱 너비와 실제 dev OAuth 왕복을 확인한다.

## 후속 기능 순서

1. 중고거래 목록·상세 조회
2. 교환 글 작성·수정·삭제와 사진 업로드
3. 채팅 목록·대화·읽음 상태
4. 알림 목록과 읽음 상태
5. 관심 매장·가챠·교환글 등록 및 해제
6. 마이페이지에서 내 교환, 채팅, 약속, 관심 항목 통합

백엔드에는 현재 중고거래와 채팅 API가 있지만, 관심 매장·가챠·교환글과 알림 API는 확인되지 않았다. 해당 단계에서는 UI보다 먼저 API 계약을 합의한다.

## 릴리스 기준

소셜 로그인은 새로운 사용자 기능이므로 패치가 아니라 minor 버전으로 관리한다. 이슈 #132가 실제 dev OAuth 검증까지 끝나면 `0.3.0` 후보가 된다.
