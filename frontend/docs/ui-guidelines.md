# 가치가챠 UI 규약

이 문서는 `frontend-v0.1.x`에서 실제로 사용해 온 화면을 기준으로 정리한 공통 규약이다. 새 화면은 이 규약을 기본값으로 사용하고, 기존 화면은 수정하는 범위 안에서 점진적으로 맞춘다. 규약을 맞추기 위한 전면 재작성은 하지 않는다.

코드의 기준값은 `src/shared/styles/tokens.ts`에 있다. 이 문서의 숫자를 컴포넌트에 다시 직접 적기보다 토큰을 가져와 사용한다.

## 1. 타이포그래피

기본 글꼴은 `Pretendard`, `Noto Sans KR`, 시스템 sans-serif 순서다. 한국어 가독성과 여러 운영체제의 폴백을 함께 고려한 구성이다.

| 역할        | 토큰           | 크기           | 굵기    | 행간    | 사용 예시                       |
| ----------- | -------------- | -------------- | ------- | ------- | ------------------------------- |
| 보조 정보   | `caption`      | 12px           | 400     | 1.4~1.5 | 사진 수, 짧은 메타 정보         |
| 라벨        | `label`        | 13px           | 600~700 | 1.4     | 상태, 버튼 보조 라벨            |
| 작은 본문   | `bodySmall`    | 14px           | 400     | 1.5     | 주소, 설명, 안내                |
| 기본 본문   | `body`         | 15px           | 400     | 1.5~1.6 | 일반 설명                       |
| 작은 제목   | `subheading`   | 17px           | 700     | 1.3     | 카드·모달 제목                  |
| 섹션 제목   | `sectionTitle` | 20px           | 700     | 1.3     | 목록 섹션 제목                  |
| 상세 제목   | `detailTitle`  | 22px           | 700~800 | 1.3     | 주요 카드 제목                  |
| 페이지 제목 | `pageTitle`    | 24~34px 반응형 | 800     | 1.3     | 오류·빈 상태 제목               |
| 대표 제목   | `display`      | 28~40px 반응형 | 800     | 1.2     | 매장명처럼 페이지의 핵심 정체성 |

- 굵기는 `400`, `600`, `700`, `800`만 사용한다. `750`처럼 팀원이 의도를 다시 해석해야 하는 중간값은 만들지 않는다.
- 중요한 이름과 페이지 제목은 말줄임표로 정보를 숨기지 않고 자연스럽게 줄바꿈한다. 가로로 흐르는 marquee 애니메이션은 읽기와 접근성이 나빠 사용하지 않는다.
- 한 줄이어야 하는 짧은 UI 라벨이나 카드의 보조 제목만 `text-overflow: ellipsis`를 허용한다. 전체 이름은 상세 화면에서 확인할 수 있어야 한다.
- 본문은 특별한 이유가 없으면 12px 아래로 내리지 않는다. 장식보다 읽기 쉬운 크기를 우선한다.
- 제목 자간은 `letterSpacing.title`, 일반 제목은 `letterSpacing.heading`을 사용하고 본문은 기본 자간을 유지한다.

## 2. 색상, 간격, 모양

- 현재 브랜드 주색은 `primary`(`#d93b54`)다. `v0.0.1`의 옛 자주색 accent 대신 현재 서비스 화면과 로고에 맞춘 값을 기준으로 한다.
- 중립색에도 이름을 붙여 `text`, `textMuted`, `textSubtle`, `border`, `surface`처럼 역할로 사용한다. 컴포넌트 안에서 비슷한 회색을 새로 만들지 않는다.
- 기본 간격은 4px 배수다. `space` 토큰의 4, 8, 12, 16, 20, 24, 32, 40, 48px 중 가장 가까운 값을 쓴다. 1~2px은 선 두께나 시각 보정에만 허용한다.
- 컨트롤, 카드, 다이얼로그의 둥근 정도는 각각 `radius.control`, `radius.card`, `radius.dialog`을 기본으로 한다. 알약 버튼은 `radius.pill`을 쓴다.
- 키보드 포커스는 `focusRing`으로 눈에 보이게 유지한다. `outline: none`만 두어 포커스를 없애지 않는다.
- 애니메이션은 상태 변화를 설명할 때만 사용하고 `prefers-reduced-motion`에서는 제거한다.

## 3. 반응형 기준

| 구간             | 토큰      | 기준        |
| ---------------- | --------- | ----------- |
| 작은 모바일      | `compact` | 최대 520px  |
| 모바일           | `mobile`  | 최대 767px  |
| 태블릿·헤더 전환 | `tablet`  | 최대 900px  |
| 넓은 팝오버 전환 | `wide`    | 최대 1080px |

- 픽셀은 폰트 최소 크기, 선, 아이콘처럼 고정되어야 하는 요소에 사용한다. 화면의 큰 영역과 열 비율은 `%`, `minmax`, `clamp`, `dvh` 등으로 뷰포트에 적응시킨다.
- 데스크톱 검색 결과는 페이지 전체가 불필요하게 길어지지 않도록 목록만 내부 스크롤하고 지도 프레임은 유지한다.
- 모바일 검색 결과는 지도를 화면의 주 영역으로 사용하고 선택된 가챠는 상단 플로팅 카드, 매장은 하단 캐러셀로 보여준다.
- 브레이크포인트가 바뀌어도 지도 드래그, 마커 선택, 확대·축소 기능은 다시 활성화되어야 한다. 처음 진입한 뷰포트에 기능 상태가 종속되면 안 된다.

## 4. 지도 화면 상호작용 규칙

지도는 단순한 배경이 아니라 목록과 같은 데이터를 다른 방식으로 탐색하는 화면이다. 다음 동작을 일관되게 유지한다.

1. 지도 이동과 서버 재조회는 분리한다. 사용자가 지도를 드래그하거나 확대해도 즉시 API를 호출하지 않고, `이 지역에서 재검색`을 눌렀을 때 현재 중심과 검색 반경으로 조회한다.
2. 현재 위치 버튼은 지도 중심만 사용자 위치로 옮긴다. 매장 재조회는 자동으로 하지 않는다.
3. 재조회할 때 사용자가 고른 줌 레벨은 유지한다. 결과를 맞춘다는 이유로 임의로 전체 매장 범위에 다시 맞추지 않는다.
4. 목록 카드와 지도 마커는 하나의 선택 상태를 공유한다. 마커를 선택하면 해당 카드가 보이는 위치로 이동하고, 카드를 선택하면 해당 마커가 지도 중심에 오도록 한다.
5. 로딩 중에는 기존 지도와 매장 결과를 가능한 한 유지한다. 새 요청 때문에 화면 전체가 하얗게 점멸하지 않도록 한다.
6. 매장 마커는 캡슐 SVG를 사용하고 선택된 매장은 열린 캡슐로 구분한다. 선택 마커에 별도의 어색한 점을 추가하지 않는다.
7. 사용자 위치는 가운데에서 균일하게 퍼지는 파란색 표시와 흰색 링으로 구분한다. 입체 구처럼 보이는 한쪽 하이라이트는 사용하지 않는다.
8. 확대·축소 버튼과 현재 위치 버튼을 함께 제공한다. 데스크톱의 마우스 휠은 페이지 스크롤과 충돌하지 않게 하고 지도 확대·축소는 명시적 컨트롤로도 가능해야 한다.
9. 모바일에서 지도 조작은 지도를 우선한다. 빈 지도 터치로 헤더를 다시 볼 수 있고, 지도 이동을 시작하면 헤더가 지도를 가리지 않도록 숨긴다.
10. 지도 SDK 실패, 위치 권한 거부, 빈 결과를 서로 다른 상태로 안내하고 다시 시도할 수단을 제공한다.

## 5. 이미지와 빈 상태

- 이미지 URL이 없거나 로드에 실패하면 공통 `LogoImagePlaceholder`를 사용한다. 깨진 이미지 아이콘이나 임의의 회색 상자를 노출하지 않는다.
- 매장 사진 영역은 매장 공간을 판단하는 자료다. 사진이 부족하다는 이유로 가챠 상품 이미지를 섞지 않는다. 상품은 별도의 `매장 보유 가챠` 영역에서 보여준다.
- 매장 사진은 대표 그리드에서 최대 5장을 미리 보여주고, 전체 개수와 `전체 사진 보기` 진입점을 제공한다. 전체 보기는 중앙 다이얼로그에서 키보드, 터치, 닫기, 포커스 복귀를 지원한다.
- 로딩 화면은 공통 로고 애니메이션을 재사용하고, 오류와 빈 결과는 원인과 다음 행동을 함께 보여준다.

## 6. 적용과 검증

- 새 컴포넌트는 토큰을 사용한다. 기존 컴포넌트는 기능 수정 시 관련 범위를 함께 옮기되, 토큰 적용만을 위한 대규모 변경은 별도 이슈로 다룬다.
- 시각 확인은 Storybook으로 고립된 상태를 먼저 보고, 지도·라우팅·API처럼 조립 후에만 확인 가능한 동작은 실제 앱에서도 확인한다.
- 최소 검증은 포맷, 린트, 타입 검사, 프로덕션 빌드다. 반응형 UI는 모바일(360px 전후), 태블릿, 데스크톱을 각각 확인한다.
- 규약 밖의 값이 더 적합하다면 사용할 수 있지만, 반복될 가능성이 있으면 토큰으로 승격하고 그 이유를 이 문서에 남긴다.

## 변경 배경

`v0.0.1`의 색상·간격·모서리·그림자·포커스 토큰은 다시 가져왔다. 다만 당시의 `sm`, `md`, `lg` 같은 크기 이름은 용도가 모호해 현재 화면에 맞는 `body`, `sectionTitle`, `card` 같은 역할 이름으로 바꿨다. 현재 버전에서 필요해진 반응형 구간, 행간, 자간, 모션, 레이아웃, z-index 기준과 지도 상호작용 규칙을 추가했다.
