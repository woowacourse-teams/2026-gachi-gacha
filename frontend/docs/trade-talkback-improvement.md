# 교환 목록·글쓰기 TalkBack 접근성 개선 기록

## 1. 목표와 범위

- 관련 이슈: [#691](https://github.com/woowacourse-teams/2026-gachi-gacha/issues/691)
- 개선 전 기준: `frontend-dev`의 `548b813f` (프론트엔드 v2.0.0)
- 개선 브랜치: `fix/691-trade-talkback`
- 설명 입력 후속 수정: [#693](https://github.com/woowacourse-teams/2026-gachi-gacha/issues/693), `fix/693-trade-description-talkback` (`9afeaaa3` 기준)
- 핵심 흐름: 교환 목록 → 글쓰기 → 제목·설명 → 카테고리 검색·추가 → 구매 매장 선택
- 목표: 화면의 배치와 정보를 유지하면서 항목의 의미, 실행할 동작, 다음 탐색 위치를 명확하게 전달한다.

필터 건너뛰기, 이미지 뷰어·모달 전반, 렌더링 성능은 이번 작업에 포함하지 않는다. 로그인·인증·등록 API도 변경하지 않는다.

## 3. 적용 내용

### 3-1. 목록보다 먼저 글쓰기에 접근

개선 전에는 모바일 글쓰기 링크가 목록과 맨 위로 버튼 뒤에 있었다. 개선 후에는 헤더 다음, 목록 앞에서 탐색할 수 있도록 DOM 순서만 조정했다.

```tsx
<AppHeader currentPath="/trade" showMobileTabs />
<CreateTradeButton placement="mobile" />
<Main>{/* 기존 목록 */}</Main>
<ScrollToTopButton />
```

- 글쓰기 링크의 접근 가능한 이름: `교환 글쓰기`
- 우측 하단 고정 위치와 반응형 표시 조건은 유지한다.
- 양수 `tabIndex`로 인위적인 순서를 만들지 않는다.

### 3-2. 카드의 항목명 안내

기존의 제목 헤딩과 카드 링크 의미는 유지하고, 화면에서 숨긴 텍스트로 값의 의미를 설명한다.

```tsx
<Meta>
  <ScreenReaderText>희망 교환 장소: </ScreenReaderText>
  {place}
</Meta>
```

안내 순서는 교환글 제목 → 카테고리 → 희망 교환 장소 → 교환글 등록 날짜 → 거래 상태다. 해당 카드에 좋아요·댓글 수가 있다면 그 의미도 함께 제공한다.

### 3-3. 제목·설명 입력 후 이동

- 제목에 `enterKeyHint="next"`를 지정하고 조합 중이 아닌 Enter에서 설명으로 이동한다.
- 한글 조합 확정 Enter는 다음 필드 이동으로 처리하지 않는다.
- 최초 개선에서 제공했던 숨은 `설명 입력을 마치고 카테고리로 이동` 버튼은 사용자 기기 피드백에 따라 #693에서 제거했다. 실제 화면에 없는 동작을 별도로 찾아야 하는 방식이 어색했기 때문이다.
- 설명은 여러 줄을 작성하는 네이티브 `textarea`를 유지한다. **Enter는 줄바꿈이며, 카테고리 이동이나 폼 제출로 바꾸지 않는다.** Shift+Enter와 여러 줄 붙여넣기, 기존 여러 줄 설명도 보존한다.
- 설명의 Enter를 ‘다음’으로 바꾸는 방안은 줄바꿈이 필요하다는 사용자 후속 요청에 따라 채택하지 않았다. 모바일 사용자가 줄바꿈을 위해 별도의 수정키를 찾아야 하는 흐름을 만들지 않는다.
- 제목의 ‘다음’과 달리 설명에는 `enterKeyHint="next"`나 Enter 이동 핸들러를 추가하지 않는다. `enterkeyhint`는 키보드 액션 표시의 힌트이며, 입력 초점과 TalkBack 접근성 초점의 복귀를 보장하는 기능이 아니다. [MDN enterkeyhint](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/enterkeyhint)
- PC의 Tab·Shift+Tab은 설명과 실제 카테고리 검색 입력란 사이의 기본 DOM 순서를 따른다. TalkBack은 기본 항목 탐색 또는 읽기 제어의 ‘제어 설정’으로 다음 입력란을 탐색한다. 중간에 별도 설명 이동 버튼은 없다.
- `blur`, 화면 높이 변경, 타이머로 초점을 강제로 되돌리는 처리는 넣지 않는다.

Google의 TalkBack 안내는 Gboard 입력 후 뒤로 동작으로 키보드를 닫는 방법을 설명한다. 다만 **사용자가 보고한 OS 뒤로가기 이후 초점이 시스템 탐색 영역에 남는 문제는 이번 변경으로 해결됐다고 판단하지 않는다.** Android Chrome과 앱 WebView에서 키보드·TalkBack 버전을 기록하고 같은 동작을 비교해야 한다. [Google TalkBack 입력·탐색 안내](https://support.google.com/accessibility/android/answer/6006598?hl=ko)

### 3-4. 카테고리 검색·선택을 독립적인 입력 영역으로 정리

카테고리 검색어·검색 결과와 선택 후 초점 처리를 `TradeCategoryField`로 분리했다. 선택한 카테고리 데이터와 등록 처리는 기존 폼이 계속 소유한다.

```tsx
<TradeCategoryField
  selectedCategories={selectedCategories}
  onSelect={selectCategory}
  onRemove={removeCategory}
  invalid={invalidField === 'category'}
/>
```

| 상황                | 처리                                                            |
| ------------------- | --------------------------------------------------------------- |
| 검색 결과 도착      | 검색어와 결과 개수를 상태 메시지로 알림                         |
| 검색 결과로 이동    | 입력창 다음의 보조 버튼 또는 키보드 검색·Enter로 첫 결과에 이동 |
| Enter 입력          | 첫 결과를 즉시 추가하지 않고, 결과를 확인할 위치로 이동         |
| 검색 결과 버튼      | 예: `치이카와 카테고리에 추가`                                  |
| 카테고리 추가       | 검색어·결과 정리, 새 선택 칩에 DOM 초점 이동                    |
| 선택한 칩           | 예: `치이카와 카테고리 선택 해제`                               |
| 선택 해제           | 다음 칩 → 이전 칩 → 검색 입력 순서로 남아 있는 대상에 초점 이동 |
| 추가 선택           | 검색 입력은 항상 탐색 가능하며 다시 검색할 수 있음              |
| 선택 완료·빈 검색어 | 비어 있는 결과 그룹과 대기 안내만 접근성 탐색에서 제외          |

검색어가 바뀌면 이전 결과를 바로 제거하고, 새 검색 결과를 기다린다. 아직 응답하지 않은 검색어에 이전 결과를 선택하는 동작을 방지한다.

### 3-5. 구매 매장·거래 장소 이름 연결

```tsx
<Label id="purchase-store-label" htmlFor="purchase-store" aria-hidden="true">
  구매 매장 <OptionalMark>(선택)</OptionalMark>
</Label>
<PlaceSelectButton
  id="purchase-store"
  aria-labelledby="purchase-store-label purchase-store-value"
  aria-haspopup="dialog"
>
  <PlaceText id="purchase-store-value">{/* 현재 값 또는 선택 안내 */}</PlaceText>
</PlaceSelectButton>
```

레이블 자체를 별도로 반복 탐색하지 않게 하고, 버튼에서 ‘구매 매장 (선택) + 현재 값 또는 선택 안내’를 함께 제공한다. 숨긴 레이블을 직접 `aria-labelledby`로 참조하는 이름 계산 규칙을 사용한다. [접근 가능한 이름 계산 규칙](https://www.w3.org/TR/accname-1.2/#computation-steps)

‘버튼’, ‘제목’ 등 역할과 텍스트가 낭독되는 순서를 웹 코드가 모든 TalkBack 환경에서 지정할 수는 없다. 역할을 지우거나 모든 요소를 일반 텍스트로 바꾸지 않는다.

### 3-6. 글자 크기·색상 낭독의 제어 범위

사용자가 보고한 ‘15픽셀, 검정색’ 안내는 TalkBack의 텍스트 서식 읽기 기능과 부합한다. Google은 TalkBack 16.2에서 글자 크기·글자색·배경색 등의 서식 안내를 제공한다고 설명한다. 기기의 TalkBack 버전과 **설정 → 상세 출력 → 텍스트 서식 말하기 / 텍스트 서식 옵션**을 확인한다. 서식 안내가 불필요하면 사용자가 해당 설정을 끌 수 있다. [Google 공식 안내](https://support.google.com/accessibility/android/answer/16800105?hl=ko)

웹 HTML/ARIA에는 ‘모든 텍스트의 내용 먼저, 서식은 나중’이라는 전역 낭독 순서를 지정하는 기능이 없다. 이를 흉내 내려고 글꼴·색상을 없애거나 콘텐츠를 숨기고 중복 낭독을 추가하지 않는다. 이번 수정은 텍스트 스타일이나 낭독 순서를 변경하지 않는다.

### 화면 변화의 범위

평소 카드·폼·고정 버튼의 배치는 유지한다. #693에서는 설명 뒤 보조 버튼만 제거하고, 사용자가 정상 동작을 확인한 카테고리 검색 결과 이동 버튼 및 선택·삭제 흐름은 유지한다. 카테고리 선택 시 검색어가 비워지고 결과가 정리되는 동작은 최초 개선에서 의도적으로 변경했다.

### 영상 2: 제목 → 설명 → 카테고리

1. 제목을 입력하고 키보드의 다음 동작으로 설명에 이동한다.
2. 설명을 두 줄 입력한다. Enter가 줄바꿈이고, 카테고리 이동이나 폼 제출이 발생하지 않는지 확인한다.
3. 뒤로가기 동작으로 키보드를 닫고, TalkBack 초점이 남는 위치를 기록한다. 시스템 버튼을 직접 선택하는 경우와 TalkBack 뒤로가기 제스처를 사용하는 경우를 구분한다.
4. TalkBack의 다음 항목 탐색 또는 읽기 제어 ‘제어 설정’으로 카테고리 검색란에 접근한다. 시스템 영역에 머문다면 복귀 성공으로 기록하지 않는다.
5. 같은 기기의 Android Chrome과 앱에서 2~4를 각각 확인한다. PC에서는 Enter·Shift+Enter 줄바꿈, 여러 줄 붙여넣기, Tab·Shift+Tab 탐색을 확인한다.

- [ ] 한글 조합 확정만으로 다음 필드에 이동하지 않는다.
- [ ] 설명의 Enter는 줄바꿈이며, 초점 이동이나 폼 제출이 발생하지 않는다.
- [ ] 설명 뒤 숨은 이동 버튼이 더 이상 탐색되지 않는다.
- [ ] Shift+Enter와 붙여넣기의 여러 줄 내용이 유지된다.
- [ ] PC에서 설명 다음 Tab 대상이 실제 카테고리 검색 입력란이다.
- [ ] TalkBack 다음 항목 탐색으로 카테고리에 도달하는지 실제 기기에서 확인했다.

### 영상 3: 카테고리 검색·추가·반복 추가

1. `치이카와` 등 검색 결과가 있는 단어를 입력한다.
2. 결과 개수 안내를 확인하고 결과 이동 보조 버튼을 실행한다.
3. `… 카테고리에 추가`를 선택한다.
4. 새 선택 칩, 비워진 검색어, 대기 안내의 반복 여부를 확인한다.
5. 검색 입력으로 돌아와 다른 카테고리를 추가하고, 하나를 해제한다.

- [ ] 검색 결과 버튼의 동작이 이름으로 명확하다.
- [ ] 선택 후 새 칩으로 초점이 이어진다.
- [ ] 빈 결과·대기 안내가 불필요하게 반복되지 않는다.
- [ ] 다시 검색·추가할 수 있다.

## 5. 검증과 결론 작성 기준

자동 테스트는 접근 가능한 이름, DOM 순서·초점, 검색 결과 정리, 한글 조합 보호, 폼 제출 회귀를 확인한다. **실제 TalkBack 낭독·OS 키보드 닫기 후 접근성 초점은 자동 검증 대상이 아니다.**

KAKAO_MAP_KEY=local-build-check POSTHOG_ENABLED=false SENTRY_ENABLED=false pnpm build
