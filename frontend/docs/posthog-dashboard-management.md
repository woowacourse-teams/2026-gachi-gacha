# PostHog 대시보드 관리 가이드

## 관리 대상

- PostHog 리전: US Cloud
- Project ID: `554216`
- 관리 스크립트: `scripts/posthog-dashboard-sync.mjs`
- 이벤트 계약: `docs/posthog-event-catalog.md`

대시보드와 인사이트는 PostHog UI에서 일회성으로만 만들지 않고 관리 스크립트에도 같은 정의를 남긴다. 누가 다시 실행해도 같은 이름의 리소스를 찾아 수정하는 방식이므로 중복 대시보드가 만들어지지 않는다.

## 로컬 자격증명

Personal API Key는 저장소나 프론트엔드 환경변수에 넣지 않는다. 이 컴퓨터에서는 다음 저장소 외부 파일에만 보관한다.

```text
~/.config/gachi-gacha/credentials/posthog.env
```

- 파일 권한: 소유자 읽기·쓰기만 가능한 `0600`
- 저장 값: `POSTHOG_PERSONAL_API_KEY`, `POSTHOG_PROJECT_ID`, `POSTHOG_HOST`
- 키 값은 문서, 이슈, PR, 터미널 출력에 남기지 않는다.
- 관리 작업이 끝난 뒤 키 노출이 의심되면 PostHog `Settings → Personal API keys`에서 즉시 회전한다.

현재 환경에는 OS 키링 도구가 설치되어 있지 않고 `systemd-creds` 장치 암호화 권한도 없어 소유자 전용 로컬 환경 파일을 사용한다. 추후 GNOME Keyring, 1Password CLI 같은 비밀 저장소를 도입하면 같은 환경변수 이름을 유지한 채 저장 위치만 교체한다.

## 실행 방법

먼저 저장된 비밀값을 현재 셸에만 불러온다.

```bash
set -a
source ~/.config/gachi-gacha/credentials/posthog.env
set +a
```

변경 계획만 확인한다.

```bash
cd frontend
pnpm run posthog:dashboards
```

검토한 정의를 실제 PostHog에 반영한다.

```bash
pnpm run posthog:dashboards -- --apply
```

스크립트는 다음 동작만 수행한다.

1. 정확히 같은 이름의 관리 대상 대시보드와 인사이트를 조회한다.
2. 없으면 생성하고, 있으면 설명·쿼리·소속 대시보드를 갱신한다.
3. 사용자나 PostHog가 만든 다른 대시보드는 삭제하거나 이름을 바꾸지 않는다.

## 운영 대시보드 구성

### `가치가챠 핵심 지표` — Dashboard `2208157`

핵심 가치를 경험한 사용자와 사업 흐름을 한 화면에서 본다. 운영자가 매일 또는 매주 확인할 대시보드이므로 고정한다.

- 최근 30일 전체 고유 사용자: 운영 환경에서 `$pageview`를 한 번 이상 발생시킨 중복 제거 방문자
- 누적 식별 회원 수: 운영 환경에서 `person.member_id`로 식별된 뒤 페이지를 조회한 중복 제거 회원
- 핵심 행동 WAU: 매장 발견, 교환글 등록 성공, 메시지 전송 성공 중 하나 이상
- 최근 30일 매장 발견 사용자
- 최근 30일 교환글 등록 성공
- 최근 30일 댓글 등록 성공
- 최근 30일 댓글 작성 후 채팅 선택
- 최근 30일 신규 채팅방
- 가챠 검색 → 매장 상세 퍼널
- 교환글 작성 → 등록 성공 퍼널
- 교환글 선택 → 메시지 전송 퍼널
- 이벤트 응모 시작 → 제출 성공 퍼널
- 사이트 방문 주간 리텐션

페이지 방문만으로 활성 사용자를 세지 않는 이유는 서비스의 실제 가치가 `매장 발견`, `교환글 공급`, `상대와의 연결`에서 발생하기 때문이다.

반면 리텐션은 처음 사이트를 방문한 사용자가 다음 주에도 다시 방문하는지를 `$pageview`로 측정한다. 향후 가챠 신상 알림처럼 재방문을 유도하는 기능의 효과를 확인하기 위해, 핵심 행동 WAU와 방문 리텐션을 서로 다른 목적으로 운영한다.

누적 식별 회원 수는 PostHog 분석 도입 이후 한 번 이상 로그인한 회원만 포함한다. 현재 프론트엔드는 OAuth 성공이 신규 가입인지 기존 회원 로그인인지 구분할 수 없으므로, 이 수치는 DB 전체 회원 수나 신규 가입자 수를 의미하지 않는다. 정확한 전체 가입자·신규 가입자 지표가 필요하면 백엔드가 구분한 회원 생성 이벤트 또는 집계 API가 추가로 필요하다.

### `[기능] 가치가챠 상세 사용` — Dashboard `2208159`

당장 KPI는 아니지만 기능 개선 때 다시 볼 행동을 모은다. 핵심 화면을 복잡하게 만들지 않으면서 저우선순위 데이터도 버리지 않기 위한 탐색용 대시보드다.

- 헤더 주요 화면 이동
- 카테고리 탐색 퍼널
- 장소 검색 채택 퍼널
- 프로필 저장 퍼널
- 프로필 사진 선택 → 업로드 → 저장 퍼널
- 거래 상세 사진 확대·전환
- 매장 사진과 보유 가챠 기능 사용
- 이벤트 완료글 증빙 포함 여부
- 업데이트 소식 조회 → 전체 변경 기록 선택
- 계정 메뉴별 사용량
- 랜딩 투어 첫 단계 → 완료 전환
- 댓글 작성 → 같은 상세 방문의 채팅 선택 전환
- 댓글 작성자 유형(회원·비회원)

### `[품질] 가치가챠 실패·복구` — Dashboard `2208160`

배포 이후 실패율과 재시도 증가를 빠르게 찾는다.

- 교환글·채팅·프로필·이벤트 응모 처리 실패
- 가챠 검색·매장 조회 실패
- 기능별 재시도
- OAuth 로그인 성공·실패
- 거래 상태 변경 성공·실패
- 프로필 이미지 검증 거절·업로드 실패
- 댓글 등록 실패

오류 메시지, 댓글·채팅 본문, 이미지 URL 같은 원문은 수집하지 않는다. 실패 원인은 제한된 열거형 속성으로만 구분한다.

## 이름과 필터 규칙

한글만 쓰면 코드와 데이터에서 어떤 이벤트인지 다시 찾아야 하고, 영문 태그만 쓰면 팀원이 대시보드를 읽기 어렵다. 따라서 다음 형식을 사용한다.

```text
한글 지표 설명 [raw_event_name.property]
```

예시:

```text
주요 화면 이동 [navigation_selected.destination]
프로필 이미지 실패 [profile_image_* outcome=failure]
```

모든 관리 인사이트에는 `environment = production` 이벤트 속성 필터를 적용한다. 프론트엔드에서 내부 사용자로 표시한 브라우저는 이벤트 전송 자체를 중단하며, 테스트 데이터는 운영 대시보드에 섞지 않는다.

## 데이터 보관 원칙

- 대시보드에 카드가 없어도 수집된 이벤트는 PostHog 원본 이벤트에 계속 저장된다.
- 중요 지표는 운영 대시보드, 채택률은 기능 대시보드, 실패는 품질 대시보드로 분류한다.
- 모든 클릭이나 렌더링을 명시적 이벤트로 만들지 않는다. 사용자의 선택, 처리 성공·실패, 퍼널 이탈을 설명할 수 있는 행동을 수집한다.
- 자동 수집은 보조 자료로만 사용하고 제품 의사결정은 타입이 정의된 명시적 이벤트를 기준으로 한다.
- 검색어·장소·댓글·채팅·파일명·이미지 URL·이메일·닉네임·Instagram ID·IP 원문은 이벤트 속성에 넣지 않는다.

## 새 기능 추가 체크리스트

1. 사용자가 시작한 행동, 성공, 실패를 구분할 수 있는지 확인한다.
2. `analyticsEventType.ts`에 이벤트와 제한된 속성 타입을 먼저 추가한다.
3. 개인정보 대신 길이, 개수, 불리언, 버킷, ID 같은 분석용 속성을 사용한다.
4. `posthog-event-catalog.md`에 발생 시점과 속성을 기록한다.
5. KPI면 운영, 기능 채택이면 기능, 실패면 품질 대시보드 정의에 추가한다.
6. 동기화 스크립트를 dry-run한 뒤 `--apply`로 반영한다.
7. PostHog Query API로 새 인사이트가 실제 실행되는지 확인한다.

## 변경 이력

### 2026-10-19

- 댓글 조회·등록 이벤트를 문서화하고 댓글 본문·닉네임·IP 원문을 수집하지 않는 기준을 명시했다.
- 댓글 등록 성공 수, 회원·비회원 구성, 같은 상세 방문에서 댓글 작성 후 채팅 선택 수를 확인하는 인사이트를 추가했다.
- 랜딩 투어 단계 조회·완료·건너뛰기, 프로필 이미지 변경, 사진 뷰어, 이벤트 완료글 증빙, 업데이트 소식 사용 이벤트를 보강했다.
- 코드로 관리하는 대시보드 정의와 실제 PostHog 구성이 어긋나지 않도록 동기화 스크립트에 같은 이름·필터를 기록했다.

### 2026-10-14

- 주간 리텐션의 시작·복귀 행동을 매장 발견에서 사이트 방문(`$pageview`)으로 변경했다.
- 운영 핵심 대시보드에 최근 30일 전체 고유 사용자(`$pageview`)를 추가했다.
- 운영 핵심 대시보드에 누적 식별 회원 수(`person.member_id`)를 추가하고 DB 전체 회원 수와의 차이를 문서화했다.
- 로컬 PostHog 관리 자격증명을 저장소 밖 소유자 전용 파일로 이동했다.
- 기본 영문 스타터 대시보드는 보존했다.
- 한국어 지표명과 원본 이벤트 태그를 병기한 운영·기능·품질 대시보드 3개를 생성했다.
- 기존 운영 데이터의 `production`·`development` 분리를 확인하고 모든 관리 인사이트에 운영 필터를 적용했다.
- 프로필 사진 선택·업로드, 거래 사진 확대·이동, 매장 사진 이동, 이벤트 완료글 증빙 여부, 업데이트 소식 사용 이벤트를 보강했다.
- 전체 관리 인사이트 27개를 PostHog Query API로 실행해 쿼리 오류가 없음을 검증했다.
