# 웹 v1.6.0 기준 Android 기능 포팅 현황

이 문서는 운영 병합 예정인 웹 서비스 v1.6.0을 Android 포팅 기준선으로 사용한다.
이벤트 응모는 종료된 기간 기능이므로 신규 앱 범위에서 제외한다. 알림 페이지는 웹도
준비 중 화면이므로 실제 알림 계약이 확정될 때 함께 구현한다.

## 권장 구현 순서

1. 네이티브 OAuth 일회성 인계와 로그인 UI
2. 신고·차단 및 마이페이지 차단 목록
3. 거래 기능 운영 활성화와 교환글 작성·수정
4. 마이페이지와 계정 관리
5. 채팅과 이미지 전송
6. 알림 센터, FCM 토큰 등록과 푸시 딥링크
7. 앱 분석·비정상 종료 추적과 성능 안정화

로그인 뒤 곧바로 사용자 생성 콘텐츠를 운영 노출하지 않는다. 신고와 차단이 실제로
동작하고 운영자가 신고를 확인할 수 있는 경로까지 검증한 다음 거래 기능을 켠다.

## 팀에서 추가로 준비할 값

- 백엔드 크루와 합의한 Android OAuth 일회성 인계 API 계약
- Firebase의 DEV/PROD Android 앱 등록과 각 환경의 `google-services.json`
- 푸시용 알림 권한 요청 시점 및 딥링크 대상 정의
- 모바일 PostHog 프로젝트 키 또는 웹과 동일 프로젝트 사용 여부
- 비정상 종료 추적 도구의 DSN과 개인정보처리방침 반영 여부

Firebase Admin 서비스 계정 private key는 앱, 저장소, GitHub Actions의 Android 빌드에
넣지 않는다. Android 클라이언트에는 Firebase Console에서 받은
`google-services.json`만 환경에 맞게 연결한다.
