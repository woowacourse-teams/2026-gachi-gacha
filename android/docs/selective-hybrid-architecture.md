# Android 선택적 하이브리드 아키텍처 결정

- 상태: 채택
- 결정일: 2026-10-27
- 적용 범위: `android/`

## 배경

운영 웹은 모바일 반응형 UI와 기능이 Android보다 먼저 완성되어 있다. 모든 화면을
React Native로 다시 만들면 웹과 앱의 표현이 어긋나고 같은 변경을 두 번 구현해야
한다. 반대로 전체 웹을 WebView로 감싸면 지도, 인증, 채팅, 이미지, 알림처럼 기기
기능과 밀접한 흐름의 안정성과 앱 고유 가치가 약해진다.

따라서 React Native 네이티브 셸은 유지하되 화면 전체를 소유권 단위로 나누어 일부
읽기 중심 화면만 WebView로 제공한다. 한 화면 안에서 작은 WebView와 네이티브 UI를
복잡하게 섞지 않는다.

## 결정

### 네이티브가 소유하는 화면과 기능

- 앱 내비게이션, 헤더, 하단 탭, 안전영역, Android 뒤로가기
- 카카오 지도, 캡슐 마커, 매장 선택과 지도 생명주기
- 시스템 브라우저 기반 OAuth, SecureStore 인증 세션
- 채팅 입력, 키보드, 이미지 선택·압축·업로드
- 알림 권한, 푸시, 딥링크, 공유와 다운로드
- 교환글 작성·수정 및 신고·차단처럼 보안 상태를 다루는 기능

### WebView 후보

- 개인정보처리방침, 약관, 공지, 패치노트, 고객지원
- 기기 권한이나 로그인 세션이 필요 없는 읽기 중심 화면
- 별도 검증을 마친 뒤 선택하는 웹의 콘텐츠 중심 화면

첫 파일럿은 공개 개인정보처리방침으로 제한한다. 회원 탈퇴 페이지는 제출 동작과
인증 계약을 별도로 검증하기 전까지 외부 브라우저에서 연다.

## WebView 안전 경계

- 화면은 임의 URL이 아니라 등록된 feature 식별자만 받는다.
- 각 feature는 HTTPS origin과 허용 경로를 중앙 설정에 등록한다.
- 허용 경로를 벗어난 링크는 WebView 안에서 탐색하지 않고 외부 앱으로 넘긴다.
- WebView에 access/refresh token을 URL, JavaScript 또는 메시지로 주입하지 않는다.
- OAuth 제공자 화면을 WebView에서 열지 않는다.
- 네이티브 브리지는 실제 요구가 확정되기 전까지 노출하지 않는다.
- 로딩, HTTP 오류, 네트워크 오류, 재시도와 웹 방문 기록 뒤로가기를 공통 처리한다.

## 지도 유지와 재평가 조건

현재 지도는 Android 네이티브 Kakao Map 모듈이 소유한다. 웹 지도의 반응형 UI가 더
완성되어 있다는 이유만으로 즉시 교체하지 않는다. 회색 화면은 먼저 네이티브 뷰의
화면 이탈·복귀, 탭 전환, 앱 백그라운드 복귀 생명주기를 재현하고 수정한다.

다음 조건을 모두 비교한 뒤에만 지도 전체 WebView 전환을 다시 검토한다.

1. 동일 실제 기기 시나리오에서 회색 화면 재현 빈도
2. 첫 표시와 화면 복귀 시간
3. 지도 제스처와 상위 스크롤 충돌 여부
4. 캡슐 마커 수가 늘어났을 때 프레임과 메모리
5. 매장 카드 포커스, 뒤로가기와 딥링크 일관성
6. Android와 iOS가 같은 동작 계약을 구현할 수 있는지

## 인증이 필요한 WebView의 선행 계약

네이티브 SecureStore와 WebView 쿠키 저장소는 자동으로 인증 상태를 공유하지 않는다.
인증 화면을 WebView로 옮기기 전 백엔드와 다음 계약이 필요하다.

- 토큰 대신 짧은 TTL의 단일 사용 handoff code만 전달
- state, provider, 환경과 요청을 서버에서 결합해 검증
- 네이티브 토큰 교환과 WebView HttpOnly 쿠키 설정을 분리
- 코드 사용 직후 폐기 및 로그 마스킹

백엔드 계약이 없는 동안 인증이 필요한 화면은 네이티브로 유지한다. Android 작업에서
백엔드 코드는 수정하지 않는다.

## 점진적 적용 순서

1. 공개 개인정보처리방침으로 공통 WebView를 실제 기기 검증한다.
2. 로딩, 오류, 뒤로가기, 외부 링크, 접근성과 데이터 수집 영향을 확인한다.
3. 네이티브 지도 회색 화면을 재현하고 생명주기를 안정화한다.
4. 지도 네이티브/WebView 비교 근거를 남기고 소유권을 유지하거나 변경한다.
5. 로그인 없는 읽기 중심 화면부터 feature flag로 추가한다.
6. 인증 handoff 계약 이후에만 로그인 화면 후보를 다시 검토한다.

패키지명, 서명키와 증가하는 versionCode를 유지하므로 선택적 하이브리드 적용은 기존
Google Play 테스트 앱의 업데이트로 배포한다.
